# Review checklist

Run this over any text before handing it back. Report each hit with the sentence and a rewrite.

## Sentences

1. Any sentence over about 35 words, in passive voice, with an empty verb, or with more than one subordinate clause?
2. Any semicolon, parenthesis outside an acronym or label definition, em dash, appositive or comma-enclosed aside?
3. Any "not X but Y", "rather than", "instead of", "is not ... it is ...", pre-emptive denial, or stacked hedge?
4. Any result sentence without a number and a reference point, vague quantity, or invented motive? More than two
   numbers in one sentence?

## Wording

5. Any abstraction or metaphor where the actual thing could be named: gap, boundary, state, guarantee, locus,
   pipeline? Any inflated or hype word: delve, pivotal, nuanced, leverage, groundbreaking? Any engineering or
   business jargon: vendor, render, verdict, surface, artifact?
6. Any sentence about how the project's code, harness, proxy or logging works, or about when a failure happens inside
   a system?
7. Any id, ticket number or file name outside the running example, teaser, case box or quoted model text?
8. Any "we call this X", "X is Y" definition, or a concept used before the reader has seen what it names? Any term,
   acronym or symbol used before it is explained? Any sentence that stacks several new objects, or a noun pile?
9. Is each thing called by one name throughout?
10. Any "see X" for outside work, instead of stating what X found?
11. Does each real-world design claim name our setup first and then the real systems, one citation each, without
    announcing realism?

## Logic

12. Does each paragraph answer one question, with sentences in the order the reader needs?
13. Does any sentence repeat something already said earlier in the section or the previous subsection?
14. Any preview or roadmap sentence, empty transition, rhythm trick or generic closing? Any line that only
    fences off scope?
15. Does each section open from the previous result or a fact that does not fit? Is each subsection a consequence, a
    rival explanation, or a follow-up on a surprise?
16. Does every finding set up an expectation and deliver the surprising half? Is each headline vivid, told with a human
    verb the way you would tell a colleague? Is "yet" used only where needed?
17. Does each headline match across abstract, contributions, finding box and caption?

## Figures and tables

18. Does each caption open with the bold finding, add at most one or two reading sentences, and end with ±SD and n?
19. Any "We test whether", notes, setup sentences, color or grid descriptions in captions?
20. Do labels say the observable thing, never ids or category names? Does any label overflow its space?

## By block

21. Method: is each component explained with intuition before the formula, is every symbol defined once, does each
    ablation say what the component contributes?
22. Benchmark: are task definition, construction, quality control and metric each complete enough to reproduce?
23. Analysis: does each finding compare against a reference, with one verbatim example?

## Scope

24. Is the human analogy only in its planned spots?
25. Any defensive line that belongs in the appendix or Limitations?
