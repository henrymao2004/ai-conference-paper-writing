# ai-conference-paper-writing

[English](README.md) | **中文**

一个 Claude Code skill，让你的 AI 论文读起来就是人习惯读的样子：一句一件事，每个结果都有数字和参照，读者第一遍就能跟上逻辑，图注第一句就是结论。

这是我改了很多轮自己的论文后总结出来的写法，和写得好的 AI 会议论文一致。方法、benchmark、分析类论文都能用，几类混在一起的论文也能用。

## 没有 AI 味

用语言模型写出来的稿子往往带着同一批习惯，读者一眼就能看出来。这个 skill 写的时候避开它们，改你的稿子时也会把它们标出来：

| 习惯 | 长什么样 | 这个 skill 怎么写 |
|---|---|---|
| 防御性写作 | "这不是 X，而是 Y""我们并不声称……" | 结论正着说 |
| 反复强调边界 | "在本文的范围内""仅在我们的设定下" | 范围只在局限一段里说一次 |
| 长难句 | 一句里三层从句、四个数字 | 拆成短句，一句一步 |
| 插入语 | 括号、分号、破折号、"如上所述，" | 每个插入的意思单独成句 |
| 难词、大词和行话 | delve、pivotal、nuanced、leverage、groundbreaking、vendor、render、verdict | 同事之间会说的普通词 |
| 名词和对象堆叠 | 还没解释就一口气列出五个新组件、"答案验证失败率" | 一次只引入一个对象，名词串拆成带动词的短语 |
| 词不解释就用 | 缩写或自造的名字先用、后解释，甚至不解释 | 每个词第一次出现就用大白话说清楚 |
| 空话和预告 | "此外""值得注意的是""本节先……再……" | 每句话说清楚它为什么接在上一句后面 |
| 节奏套路 | 凑满三项的排比、正文里到处加粗 | 正文就写成正文 |
| 没有依据的论断 | "显著更好""模型想要……" | 给出数字和参照，原因只谨慎说一次 |

## 能做什么

- **写和改**任何一节：摘要、引言、贡献、方法、benchmark 构造、实验、分析、相关工作、局限、讨论、图注，还有博客。
- **结构贴合你的论文**：识别论文里的方法、benchmark、分析几个部分，按主贡献定骨架，几部分混在一起时各自保留自己的写法。
- **发现写得有力**：每个结果都带数字和参照；分析类的发现先写读者本来以为会怎样，再写实际发生了什么。
- **图注和图**：第一句加粗写结论，后面只写读图需要的东西。
- **自查**：按句子、用词、逻辑、图表和 AI 味逐项检查，每条附改写。
- **向你喜欢的论文学（可选）**：可以给几篇参考论文（.tex 或 .pdf），它按节和段落切开，判断每部分是方法、benchmark 还是分析，生成一份简短的风格档案，你的论文就照着写。不给参考论文时，用它自带的写法。

## 安装

```bash
git clone https://github.com/henrymao2004/ai-conference-paper-writing ~/.claude/skills/ai-conference-paper-writing
```

重启 Claude Code。写或改论文时它会自动调用，也可以用 `/ai-conference-paper-writing` 直接调用。

## 用法

- "帮我改写方法一节的这一段。"
- "精简引言，顺便查一下有没有重复。"
- "查一下我的稿子有没有 AI 味。"
- "给图 2 到图 4 写图注。"
- "这三篇是我喜欢的论文，先学它们的风格：a.tex、b.pdf、c.pdf。"
